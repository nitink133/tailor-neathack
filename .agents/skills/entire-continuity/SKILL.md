# Entire continuity

This skill guides verification; loading it does not install or guarantee hooks. Check evidence in the actual agent session, binary and worktree. Keep live capture, historical import, local checkpoint linkage, remote ref sync and dashboard ingestion as separate findings. Aggregate Analytics is not session evidence; ignore the known Tailor Analytics discrepancy.

## Scope and authority

The maintained source is `.agents/skills/entire-continuity` in this repository. Use the copy tracked in the current checkout; older worktrees must integrate the approved source commit before expecting automatic discovery. Do not create global copies or cross-worktree symlinks.

Use existing authorization for ordinary task work. This skill alone authorizes no commits, pushes, imports, attachment, transcript uploads, scheduled checks or hidden automation. Weekly use means only an explicitly requested evidence review within this repository; it changes no approval rules and authorizes no autonomous check or schedule. Do not expand access or transmit credentials. Work only on the personal Mac; exclude StockGro and office projects.

Do not alter global Git config, authentication, hooks, trust records, permissions or credentials. Do not stop other sessions or repair dirty/diverged checkouts. Preserve checkpoint refs, original commit identities and other agents' work; never synthesize checkpoint trailers or claim retrospective live capture. Repairs need authorization for the concrete repair. Import/attach need explicit permission; attaching can amend HEAD, so permission to import is not permission to amend or force-push.

## Task-start preflight

1. Resolve the intended repository, checkout and shared Git directory with `git --no-optional-locks rev-parse --show-toplevel --git-common-dir`. Inspect `git --no-optional-locks status --porcelain=v1 --branch`, `git rev-parse HEAD`, `git symbolic-ref --quiet --short HEAD`, and upstream identity/divergence when present. Keep paths and SHA evidence; do not print file contents, remote URLs with embedded credentials, or full commit messages. A dirty checkout, detached HEAD, missing upstream or divergence is a finding, not permission to reset, stash, amend, fetch or switch branches. Existing upstream refs are cached evidence only.
2. Confirm Entire is already enabled from approved metadata or bounded settings inspection. If unrelated/unconfigured, report exclusion and stop this skill without enabling anything. In Tailor, inspect the existing worktree documentation when needed: `docs/entire-codex-worktrees.md` relative to the current checkout root. Never mutate that worktree or its branches as part of skill verification.
3. Run `entire version` and the actual session binary's `--version`; PATH Codex may differ from the desktop bundle. Verify syntax using installed `--help` and the matching tagged official docs. Reviewed baseline: Entire 0.11.4, desktop-bundled Codex 0.162.0-alpha.17.2, PATH Codex 0.153.4. Recheck after upgrades; the official integration tests pin Codex 0.149.0 and do not prove every newer surface works.
4. Check hook discovery, configured commands/timeouts, Git-hook wiring and trust separately from capture. Use already available status/doctor evidence or bounded approved inspection. `entire status --json` can reconcile exited sessions; `entire doctor </dev/null` is a noninteractive diagnostic, not a promise of zero state changes. Do not run either on shared live state when strict observation is required; report that diagnostic boundary instead. Never use `doctor --force`, enable/configure, run hook handlers manually, or fabricate trust hashes for verification. Review untrusted hooks through the user's Codex `/hooks` flow only when authorized.
5. Use `entire session current --json` (metadata only). Only `resolution` = `caller-env` or `ancestry` identifies the command's caller. Recent-worktree and `other-worktree` fallback are not proof of this session. Match caller ID, worktree and branch; inspect `entire session info <session-id> --json`. Require active state plus fresh lifecycle evidence from this caller during the current task before claiming live capture. An ID, installed hook file, trusted/discovered hook, old active record or historical checkpoint alone is insufficient. If freshness/source cannot be established without denied transcript access, mark live capture unverified. Never use `--transcript`, full/raw modes, denied transcript paths, or dump JSON metadata wholesale; project only safe IDs, paths, state, times, linkage and usage fields.

Conventional linked worktrees may discover the primary checkout's hook file rather than their own. Read ownership is not write ownership: compare the resolved discovered path, current-checkout path, project layer and trust. `worktree_path_not_discovered` may coexist with `ACTIVE (via root checkout)`; reconcile paths instead of blindly reinstalling. A branch lacking `.codex` can have a project-layer gap. Never copy/migrate hooks between worktrees or edit another checkout to resolve this.

## After meaningful authorized commits and pushes

Before an already-authorized commit, record original HEAD and bounded checkpoint ref identities. Let normal Git hooks perform capture; do not create a verification commit. Afterwards resolve the exact new SHA and extract only `Entire-Checkpoint` trailers (for example with Git's `%(trailers:key=Entire-Checkpoint,valueonly)` format). Inspect metadata with `entire checkpoint explain --commit <exact-sha> --json` and `entire checkpoint list --session <exact-session-id> --json`; the latter is branch-scoped. Match exact commit, checkpoint and session IDs, including multi-session checkpoints. Never equate an empty branch-scoped list with deletion of all history. Missing linkage is a failure to verify, not a reason to amend the commit.

For git-refs storage, the checkpoint ref is `refs/entire/checkpoints/<last-two-ID-characters>/<id>`. Read the local ref SHA using Git; absence means local checkpoint unverified. Keep existing checkpoint refs intact, including legacy storage. Inspect selected metadata only; checkpoint trees contain private session content. Missing/null usage or incomplete child accounting is **unavailable**, not zero; report zero only if explicitly recorded.

Before an authorized push, establish the selected checkpoint destination and push_sessions setting from existing safe evidence. A normal code push can transmit transcript-derived checkpoint data; existing push authorization must cover that configured destination and content. If it does not, pause the push with the concrete missing scope. Never manually push shadow branches or change remotes/credentials. Afterwards compare each relevant local checkpoint ref SHA with the same exact ref returned by `git ls-remote --refs <approved-remote-name> <exact-ref>`; this is a remote read using existing access, not permission to authenticate anew. Bound runtime and output. If no safely established destination exists, report sync unknown. A local checkpoint, successful code push, cached origin ref or matching count alone does not prove checkpoint sync. Equal exact SHAs prove ref sync at observation time; dashboard linkage/ingestion requires separately observed session or commit view/API evidence. Don't gate this on Analytics.

## Handoff, weekly check and failures

Repeat the caller/linkage checks at handoff; an ended session with prior live evidence is valid handoff evidence, not currently active capture. Summarize repository/worktree, agent surface and binary version, session/resolution/state and freshness, original/current commit, checkpoint/local SHA, remote name/SHA and observation time, usage availability, dashboard evidence and outstanding boundary. Preserve evidence outside the repository only in an authorized location, excluding prompts and credentials.

If the surface is unsupported or capture is missing, give the exact boundary and smallest next step: e.g. discovered hooks but no caller state → an authorized fresh/resumed session in that worktree with reviewed hooks, then metadata verification. Continue authorized coding if appropriate, clearly marking capture unverified. Never relabel an import as live. For requested historical recovery, first inspect `entire import --help`, the agent-specific import help, and `entire session attach --help`; explain local-history versus commit-linkage effects and request the exact missing mutation permission before execution. No automatic amend, force, upload or live test commit.

Optional repeatability helper: `python3 <skill-dir>/scripts/classify_evidence.py <sanitized-evidence.json>`. Read its short input contract before use. It classifies manually normalized evidence, does not collect/verify facts, and performs no Git, Entire, network or transcript operations. Unknown facts stay unknown. For an explicitly requested weekly evidence review, invoke this skill and sample the week's exact authorized commits and checkpoints within the selected repository; report coverage limits, not universal completeness.
