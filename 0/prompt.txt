PRODUCT OUTCOME
Tailor helps an anonymous buyer understand how Neatlogs could help their project through a personalised synthetic demo. It is more than a chatbot describing features.
Example acceptance journey:
A buyer says, “I’m building a travel-booking agent. Show me a booking API timeout followed by a successful retry.” Tailor prepares a coherent fictional trace visible in the existing Neatlogs-style UI. The buyer then says, “Make the retry fail too.” Tailor updates that session’s scenario, verifies the saved spans and explains the resulting failure and escalation.
Current code has a working UI, SQLite state and two fixed fixtures selected by keyword matching. It does not yet establish a live agent or a source-backed vendor knowledge layer. Extend it without rebuilding the clone.
ARCHITECTURE
- One server-side product agent. The coding swarm does not imply a multi-agent product runtime.
- Versioned repository files for Neatlogs product knowledge, capability definitions and tool contracts. No new memory vendor or vector database for this slice.
- SQLite for active anonymous buyer conversations and authoritative demo state.
- Load relevant knowledge, conversation context and current scenario version for each turn.
- The model interprets requests, asks clarifications, proposes bounded actions and explains verified results.
- Deterministic code enforces permissions, schemas, relationships, timing consistency, session ownership and version checks.
- Save transactionally, read back independently and only then claim the change succeeded.
